# ENH: consider a limited-memory regularized quasi-Newton method for scipy.optimize.minimize

Hello, SciPy maintainers.
I'm Hiroki Hamaguchi, a doctoral student working in numerical optimization.

I greatly appreciate your work on SciPy, and I would like to discuss a possible addition to `scipy.optimize.minimize`.

(I previously mentioned this work in my presentation at [SciPyData 2026](https://scipydata.connpass.com/event/364718/) in Japan.)

This issue has two related motivations:

1. On some problems, the current L-BFGS-B implementation has a relatively large wall-clock cost per iteration.
2. Recent regularized quasi-Newton methods provide an alternative to the traditional line-search L-BFGS framework and may be faster or more robust on some problems.

I am therefore considering adding a new, Python-based, limited-memory regularized quasi-Newton method as an additional `minimize` method, but this plan is still tentative.

In this issue, I would like to ask whether this would be a reasonable direction for SciPy, and if so, whether you have any suggestions for the API or other design considerations.

## Motivations

### Per-iteration wall-clock cost

The first motivation is the current L-BFGS-B overhead.

SciPy's current implementation is written in [C](https://github.com/scipy/scipy/blob/main/scipy/optimize/src/lbfgsb.c), exposed through Python by [`minimize(method="L-BFGS-B")`](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-lbfgsb.html).

I would first like to clarify that this point is not directly related to the recent [SciPy issue #23191](https://github.com/scipy/scipy/issues/23191), which reports a performance regression between SciPy 1.14 and releases from 1.15 onward and discusses OpenBLAS thread behavior as an important possible cause.

(I also have some interest in this issue, but I do not intend to discuss it further here.)

The key observation is that, on some problems, the current L-BFGS-B implementation has a relatively large wall-clock cost per iteration, regardless of the SciPy version or BLAS threading behavior.

The following figures are the benchmark results of the current L-BFGS-B implementation and our Python-based limited-memory quasi-Newton methods on two simple problems.
Please note that these results only illustrate the per-iteration wall-clock cost, which is independent of the theoretical efficiency of the optimization method.

As shown, our methods have lower per-iteration wall-clock costs at many of the tested dimensions. Our methods can be more than 2 times faster than the current L-BFGS-B implementation at some dimensions.
The main exceptions are small problems and dimensions near the BLAS threading crossover around $n=10^4$.

This might be due to unavoidable Python--C transition overhead in the current implementation.

This is one of the motivations for proposing a new solver.

### Recent progress in quasi-Newton methods

The second motivation is recent progress in quasi-Newton methods.

The method I would like to propose in the future is the noise-tolerant regularized quasi-Newton method (NTRQN) described in our paper: [https://arxiv.org/abs/2603.10642](https://arxiv.org/abs/2603.10642).

(I would like to make clear that this proposal is not intended as self-promotion. If the maintainers consider the method unsuitable, I will not pursue the proposal.)

Although the particular combination is ours, many of its components build on developments from the numerical optimization literature over the past several decades:

- **Regularized quasi-Newton directions:** these methods compute a direction corresponding to $-(B_k+\mu_k I)^{-1}g_k$, following regularized Newton and limited-memory RQN work ([Ueda and Yamashita, 2014](https://doi.org/10.1007/s10589-014-9656-x); [Kanzow and Steck, 2023](https://doi.org/10.1007/s12532-023-00238-4)). Compared with line-search L-BFGS, this approach can be more robust or faster on some problems.
- **Curvature safeguards independent of Wolfe success:** damped BFGS and cautious selection of stored pairs maintain usable, spectrally bounded limited-memory approximations. This follows the cautious-update tradition ([Li and Fukushima, 2001](https://doi.org/10.1137/S1052623499354242)).
- **Optional modified secant information:** when function values are reliable, information from function-value interpolation can improve the curvature model, following the modified-secant literature ([Zhang, Deng and Chen, 1999](https://doi.org/10.1023/A:1021898630001); [Yabe, Ogasawara and Yoshino, 2007](https://doi.org/10.1016/j.cam.2006.05.018)). Roughly speaking, this incorporates function-value interpolation, similar to that used in the Moré--Thuente line search in L-BFGS-B, into the quasi-Newton model update itself.
- **Use function values only when they are informative:** a relaxed, non-monotone Armijo test keeps ordinary quasi-Newton behavior when sufficient progress is observable. Otherwise, positive regularization is controlled by accumulated gradient norms, following the Objective-Function-Free Optimization (OFFO)/AdaGrad-Norm line of work ([Gratton, Jerad and Toint, 2024](https://doi.org/10.1080/10556788.2023.2296431), [Our paper](https://arxiv.org/abs/2603.10642)).

## Benchmarking

Below are some benchmark results illustrating the performance of the proposed method.

[CUTEst](https://doi.org/10.1007/s10589-014-9687-3) is a standard collection and testing environment for optimization problems.
We conducted tests on 220 unconstrained problems at 64-bit precision and 124 at 32-bit precision.
The limited-memory methods used $m=10$, and the maximum iteration count was 15,000.

The primary figures use Dolan--Moré [performance profiles](https://doi.org/10.1007/s101070100263).
For problem $p$ and solver $s$, the ratio is $r_{p,s}=\frac{n_{p,s}}{\min_{s'} n_{p,s'}}$, where $n_{p,s}$ is the number of oracle calls (i.e., function and gradient evaluations) required to reach the stated gradient tolerance (and is infinite on failure).
At $\tau=1$, the height is the fraction of problems on which a solver was best.
At larger $\tau$, the height is the fraction solved within $\tau$ times the best solver's oracle count.
The final height therefore indicates robustness/coverage.

We note that these benchmark results only illustrate the number of oracle calls, not the wall-clock time (to maintain the reproducibility and fairness of the benchmark).
Combined with the low per-iteration wall-clock cost mentioned above, these results suggest that our method would be competitive in wall-clock time on many problems.

We plan to prepare a full set of wall-clock-time benchmark results before I formally submit a PR to SciPy.
Our paper is currently under review, and these results may be updated.

## Box constraints (the "-B" in L-BFGS-B)

The method can be extended to box constraints, which would be necessary for a full L-BFGS-B replacement.

A working prototype, [`qnlab/solver/qn_ntrqnb.py`](https://github.com/HirokiHamaguchi/qnlab/blob/main/qnlab/solver/qn_ntrqnb.py), combines our method with a generalized Cauchy point and is able to solve box-constrained problems.

However, I do not currently plan to include this box-constrained variant.
It would add substantial implementation and maintenance cost.
Box support could be considered later if there is sufficient user and maintainer interest.
